## 🔬 Research & Enrichment

### Overview
This is Kedhareswer's personal data science portfolio website, deployed via GitHub Pages at kedhareswer.github.io/MyPortfolio. The live site is organized into Skills, Education, Experience, Projects, and Contact sections, and showcases data analysis / ML work (e.g. "GreenPlay Matrix" — games-vs-violence analysis using ML/NLP/EDA, and "Analysis on Video Game Industry") alongside certification pages (Python, SQL, R, Excel, Tableau, Power BI, ML, PM). Note a discrepancy with the catalog metadata: the source lists "Streamlit," but the actual repo (`Kedhareswer/MyPortfolio`) is plain hand-coded HTML/CSS/JS (~68% HTML, ~30% CSS, ~2% JS), not a Streamlit app.

### Why it matters
A portfolio is the single highest-leverage asset for breaking into data roles: ~62% of recruiters spend under 30 seconds per portfolio, so a scannable, credible landing page directly affects callback rates. It gives employers a place to see how a candidate frames problems, communicates insight, and proves skills beyond a CV — increasingly the differentiator as employers prize storytelling over raw model accuracy.

### How it works / Recommended approach
The site is a static multi-page build: `index.html` as the landing page, `style.css`/`style1.css` for styling, `javascript.js` for light interactivity, individual `project*.html` pages, and per-certificate HTML pages, with an `images/` asset folder for skill icons and photos. It is served free as a static site through GitHub Pages from the repo. There is currently no README on either the `main` or `master` branch.

### State of the art & comparable work
Modern DS portfolios trend toward templated, content-driven sites and interactive demos rather than hand-rolled HTML. Comparable named options: [al-folio](https://github.com/alshedivat/al-folio) (Jekyll, dark mode, auto-CV); [academicpages](https://github.com/academicpages/academicpages.github.io); [datascienceportfol.io](https://www.datascienceportfol.io/) (hosted builder); and curated project portfolios like [sajal2692/data-science-portfolio](https://github.com/sajal2692/data-science-portfolio). For interactive ML demos, [Streamlit Community Cloud](https://streamlit.io/) is the standard; for BI storytelling, Tableau/Power BI dashboards remain highly competitive for analytics roles.

### Tech stack
HTML5, CSS3, vanilla JavaScript, GitHub Pages (static hosting). Showcased tool skills: Python, SQL/MySQL, R, Excel, Tableau, Power BI, ML/NLP.

### Key challenges & risks
- Catalog says "Streamlit" but the repo is static HTML — metadata should be corrected to avoid mismatched expectations.
- No README means weak discoverability and no project narratives for skimming recruiters.
- Hand-coded HTML is harder to maintain/scale than a templated (Jekyll/Astro) site as projects grow.
- Projects risk reading as "tutorial-level" without unique datasets and clear business-outcome framing.

### Suggested next steps
- Add a README with a project index, screenshots, and links to code + write-ups.
- Reframe each project around business impact (e.g. quantified outcomes) rather than just accuracy.
- Embed or link 1–2 interactive Streamlit demos to show end-to-end, deployable work.
- Migrate to a maintainable template (al-folio/Astro) or add a responsive, mobile-first refactor.
- Ensure clean, commented code repos behind each featured project; add a downloadable resume.
- Correct the portfolio metadata (drop "Streamlit," reflect HTML/CSS/JS + GitHub Pages).
